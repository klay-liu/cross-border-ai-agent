## 一、战略总览

### 1.1 核心命题

传统跨境电商的「人力密集型运营」正在被 AI Agent 范式颠覆。核心转变：

```
传统模式：人 → 工具 → 决策 → 执行（人是瓶颈）
Agent模式：数据 → Agent感知 → Agent推理 → Agent执行/人审批（AI是引擎）
```

对于「一人操盘」的五金跨境电商模式，AI Agent 不是锦上添花，而是**生存必需**——它是让一个人做到三个人效率的唯一路径。

## 二、场景优先级矩阵

基于 **业务影响力 × 技术可行性 × 实现复杂度** 三维评估：

| 优先级 | Agent 场景 | 业务影响 | 技术可行性 | 复杂度 | ROI 评分 | 落地阶段 |

### 2.2 优先级决策逻辑

**为什么「选品 + 市场洞察」是 P0？**

1. **选品决定生死**：五金跨境电商的核心风险在选品——选错品，后续运营再好也白搭
2. **数据密集型任务**：需要交叉分析 Amazon 搜索量、竞品评论、价格趋势、供应链成本等多维度数据，正是 Agent 擅长的
3. **现有痛点**：当前选品依赖人工刷榜 + 经验判断，效率低且容易遗漏蓝海机会
4. **复用性强**：选品 Agent 的数据采集能力可直接复用于竞品监控、定价分析等下游场景
5. **验证路径最短**：从已有的 Amazon 市场调研数据（弹簧、U型螺栓等）可直接验证 Agent 输出质量

## 三、ROI 分析

### 3.1 各场景 ROI 量化

#### 智能选品 Agent

| 指标 | 传统方式 | Agent 方式 | 提升幅度 |
|------|---------|-----------|---------|
| 单次选品周期 | 3-5天 | 2-4小时 | **10-15x** |
| 候选品覆盖率 | 50-100 SKU | 1000+ SKU | **10x** |
| 选品成功率 | 20-30% | 45-60%（预估） | **2x** |
| 月度选品次数 | 1-2次 | 持续/按需 | **∞** |
| 漏掉的蓝海机会 | 不可知 | 系统性扫描覆盖 | — |

**ROI 计算**：
- 假设选品成功率从 25% 提升到 50%
- 首批 5 个 SKU，每个 SKU 测试成本 ¥3000
- 传统方式：5 SKU 中 1.25 个成功 → 浪费 ¥11,250
- Agent 方式：5 SKU 中 2.5 个成功 → 浪费 ¥7,500
- **单批次节省 ¥3,750，年化节省 ¥15,000+**

#### 市场洞察 Agent

| 指标 | 传统方式 | Agent 方式 | 提升幅度 |
|------|---------|-----------|---------|
| 竞品价格追踪 | 手动/周频 | 实时自动 | **持续** |
| 差评痛点挖掘 | 人工阅读 | NLP 批量分析 | **50x** |
| 趋势发现速度 | 落后市场 1-2 周 | 接近实时 | **7-14天** |
| 覆盖竞品数量 | 10-20 | 100+ | **5-10x** |

**ROI 计算**：
- 提前 7 天发现价格战/竞品断货 → 及时调整策略
- 假设每月避免 1 次 ¥2000 的错误决策
- **年化节省 ¥24,000**

#### 综合 ROI

| 投入项 | 金额 |
|--------|------|
| AI API 费用（Claude/GPT） | ¥500-1000/月 |
| 数据源订阅（Keepa/SP-API） | ¥500-800/月 |
| 服务器/部署 | ¥200-500/月 |
| **月度总投入** | **¥1,200-2,300** |
| **月度预期收益** | **¥3,000-5,000**（节省 + 增量） |
| **ROI** | **2.2x - 4.2x** |

### 3.2 非量化收益

- **决策质量提升**：基于数据而非直觉
- **运营效率释放**：省出的时间用于品牌建设、供应链优化等高价值活动
- **系统性壁垒**：AI Agent 体系一旦建成，是竞争对手难以复制的差异化
- **可扩展性**：同一套系统可快速复制到新品类、新站点

## 四、阶段路线图

**目标**：构建选品 + 市场洞察 Agent 核心能力，验证 AI 辅助决策的价值

┌────────────────────────────────────────────────────────────┐
│ Phase 1: MVP 验证                                          │
│                                                            │
│ M1: 基础建设                                                │
│ ├── 数据采集管道搭建（Amazon SP-API / Keepa / 爬虫）         │
│ ├── LLM 集成框架（Claude API / Function Calling）           │
│ ├── 选品 Agent v0.1（关键词分析 + 竞争度评估）               │
│ └── 市场洞察 Agent v0.1（差评分析 + 价格监控）               │
│                                                            │
│ M2: 功能迭代                                                │
│ ├── 选品 Agent v0.2（利润率计算 + 供应链匹配）               │
│ ├── 市场洞察 Agent v0.2（趋势追踪 + 竞品矩阵）             │
│ ├── 竞品监控 Agent v0.1（价格/库存/评论变动告警）            │
│ └── 输出对接（飞书/Notion Dashboard）                       │
│                                                            │
│ M3: 验证与优化                                              │
│ ├── 用 Agent 完成首批 5 SKU 选品决策                         │
│ ├── 对比 Agent 推荐 vs 人工判断的准确性                      │
│ ├── Listing 优化 Agent v0.1（标题/五点生成）                 │

└────────────────────────────────────────────────────────────┘

**Phase 1 技术栈**：
- LLM：Claude 3.5 Sonnet（主推理） + Haiku（轻量任务）
- 数据采集：Python + Playwright/Puppeteer + Amazon SP-API
- Agent 框架：LangChain / 自研轻量框架
- 存储：SQLite（MVP）→ PostgreSQL（后期）
- 部署：本地运行 → Docker 容器化
- 通知：飞书 Webhook / 微信推送

## 六、风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| Amazon API 限制/封禁 | 中 | 高 | 多数据源冗余（Keepa + Helium10 + 爬虫）；遵守 TOS |
| LLM 幻觉导致错误决策 | 中 | 高 | 关键决策必须人工审批；交叉验证；置信度评分 |
| 数据采集成本超预期 | 低 | 中 | 分级采集策略（高频品全量，长尾品抽样） |
| Agent 维护成本高 | 中 | 中 | 模块化设计；充分测试；渐进式迭代 |
| 竞品也用 AI，优势被抹平 | 高 | 中 | 核心壁垒在数据积累和业务 know-how，不仅在技术 |

### 7.2 工具选型对比

| 需求 | 候选方案 | 选择 | 理由 |
|------|---------|------|------|
| LLM | Claude / GPT-4 / 开源 | **Claude** | Function Calling 能力强，中文理解好，API 稳定 |
| Agent 框架 | LangChain / CrewAI / 自研 | **自研轻量** | MVP 阶段不需要重框架，降低调试成本 |
| 数据采集 | SP-API / Keepa / 爬虫 | **混合** | SP-API 为主，Keepa 补充历史数据，爬虫兜底 |
| 存储 | SQLite / PostgreSQL / MongoDB | **SQLite → PG** | MVP 用 SQLite 足够，后期迁移 PostgreSQL |
| 调度 | Cron / Celery / APScheduler | **APScheduler** | Python 原生，轻量，满足 MVP 需求 |
| 通知 | 飞书 / 微信 / Slack | **飞书** | 支持 Webhook + 机器人，国内团队友好 |
