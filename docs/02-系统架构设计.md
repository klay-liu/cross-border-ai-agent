### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **Agent 自治** | 每个 Agent 独立运行，拥有自己的工具集和决策逻辑 |
| **人在回路** | 关键决策（选品确认、价格调整）必须人工审批 |
| **数据驱动** | 所有决策基于可追溯的数据证据链 |
| **渐进增强** | 从 MVP 开始，验证后再增加复杂度 |
| **模块解耦** | Agent 间通过消息/事件通信，可独立升级替换 |
| **成本可控** | LLM 调用按需分级，避免不必要的 token 消耗 |

## 三、数据采集层设计

### 3.1 数据源矩阵

| 数据源 | 数据类型 | 获取方式 | 频率 | 成本 |
|--------|---------|---------|------|------|
| **Amazon SP-API** | 搜索结果、产品详情、类目排名 | 官方 API | 按需 | 免费（需卖家账户） |
| **Keepa API** | 历史价格、销量估算、BSR 趋势 | REST API | 日频/周频 | ~$20/月 |
| **Amazon 前端** | 评论内容、Q&A、竞品 Listing | Playwright 爬虫 | 按需 | 服务器成本 |
| **Google Trends** | 搜索趋势、地域分布 | API/爬虫 | 周频 | 免费 |
| **Jungle Scout** | 选品数据、关键词数据 | 导出/API | 按需 | ~$50/月（可选） |
| **1688/工厂系统** | 供应链成本、产能 | 手动录入/API | 按需 | 免费 |

### 3.2 数据模型

```sql
-- 核心数据表

-- 产品表：存储所有跟踪的 Amazon 产品
CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    asin TEXT UNIQUE NOT NULL,
    title TEXT,
    brand TEXT,
    category TEXT,
    price REAL,
    rating REAL,
    review_count INTEGER,
    bsr_rank INTEGER,
    monthly_sales_est INTEGER,
    monthly_revenue_est REAL,
    fba_fee REAL,
    referral_fee_pct REAL,
    image_url TEXT,
    first_seen_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 价格历史表：追踪价格变动
CREATE TABLE price_history (
    id INTEGER PRIMARY KEY,
    asin TEXT NOT NULL,
    price REAL,
    bsr_rank INTEGER,
    review_count INTEGER,
    rating REAL,
    recorded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (asin) REFERENCES products(asin)
);

-- 评论分析表：存储差评痛点挖掘结果
CREATE TABLE review_analysis (
    id INTEGER PRIMARY KEY,
    asin TEXT NOT NULL,
    review_id TEXT,
    rating INTEGER,
    review_text TEXT,
    pain_point TEXT,          -- LLM 提取的痛点
    pain_category TEXT,       -- 痛点分类（质量/尺寸/包装/功能）
    improvement_suggestion TEXT, -- LLM 生成的改进建议
    analyzed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (asin) REFERENCES products(asin)
);

-- 选品候选表：Agent 生成的选品建议
CREATE TABLE product_candidates (
    id INTEGER PRIMARY KEY,
    keyword TEXT NOT NULL,
    asin TEXT,
    opportunity_score REAL,    -- 0-100 综合机会评分
    competition_score REAL,    -- 0-100 竞争度评分（越低越好）
    demand_score REAL,         -- 0-100 需求评分
    profit_potential REAL,     -- 预估利润率
    factory_match_score REAL,  -- 0-100 工厂匹配度
    recommendation TEXT,       -- LLM 的推荐理由
    status TEXT DEFAULT 'pending', -- pending/approved/rejected
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 竞品监控表：竞品变动事件
CREATE TABLE competitor_events (
    id INTEGER PRIMARY KEY,
    asin TEXT NOT NULL,
    event_type TEXT,          -- price_change/stock_out/new_review/bsr_change
    old_value TEXT,
    new_value TEXT,
    severity TEXT,            -- low/medium/high/critical
    notified INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (asin) REFERENCES products(asin)
);

-- 市场趋势表：存储趋势洞察
CREATE TABLE market_trends (
    id INTEGER PRIMARY KEY,
    category TEXT,
    keyword TEXT,
    trend_direction TEXT,      -- rising/stable/declining
    search_volume_est INTEGER,
    growth_rate REAL,
    insight TEXT,              -- LLM 生成的趋势分析
    data_source TEXT,
    recorded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Agent 执行日志
CREATE TABLE agent_runs (
    id INTEGER PRIMARY KEY,
    agent_name TEXT NOT NULL,
    task_type TEXT,
    input_params TEXT,         -- JSON
    output_summary TEXT,
    tokens_used INTEGER,
    cost_usd REAL,
    duration_seconds REAL,
    status TEXT,               -- running/completed/failed
    started_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    completed_at TIMESTAMP
);
```

### 4.2 工具接口规范

```python
# 统一的 Tool 接口定义
class Tool:
    name: str           # 工具名称
    description: str    # 工具描述（供 LLM 理解）
    parameters: dict    # JSON Schema 参数定义

    def execute(self, **kwargs) -> ToolResult:
        """执行工具，返回结构化结果"""
        pass

class ToolResult:
    success: bool
    data: Any           # 返回数据
    error: str | None   # 错误信息
    tokens_used: int    # LLM token 消耗（如有）
    cost: float         # 成本（如有）
```

## 六、LLM 集成策略

### 6.1 模型分级使用

| 任务类型 | 模型选择 | 原因 | 单次成本 |
|---------|---------|------|---------|
| 选品深度分析 | Claude Sonnet | 需要复杂推理和长上下文 | ~$0.02-0.05 |
| 差评痛点提取 | Claude Sonnet | 需要准确的语义理解 | ~$0.01-0.03 |
| 竞品变动摘要 | Claude Haiku | 结构化数据简单摘要 | ~$0.001 |
| Listing 生成 | Claude Sonnet | 需要创意和营销理解 | ~$0.03-0.05 |
| 日报生成 | Claude Haiku | 模板化输出 | ~$0.002 |
| 数据清洗/格式化 | 不用 LLM | 规则引擎处理 | $0 |

## 八、安全与合规

### 8.1 API 安全

| 措施 | 说明 |
|------|------|
| 密钥管理 | 使用 .env 文件 + dotenv 加载，不入代码仓库 |
| 请求频率控制 | 遵守各 API 的 rate limit，内置退避重试 |
| 数据加密 | 敏感数据（API key、卖家数据）加密存储 |

### 8.2 Amazon 合规

| 规则 | 对应措施 |
|------|---------|
| SP-API TOS | 仅使用授权数据，不超出权限范围 |
| 爬虫限制 | 低频抓取 + 随机延迟 + 尊重 robots.txt |
| 数据使用 | 仅用于自有店铺运营决策，不转售数据 |
